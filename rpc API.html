Remote Procedure Call (RPC) Concept

How distributed systems communicate seamlessly

What is RPC?

Remote Procedure Call (RPC) is a protocol that allows a computer program to execute a procedure (subroutine or function) on another address space, typically on another computer on a shared network. This is done in a way that appears to the programmer as a normal local procedure call, abstracting away the complexities of network communication.

Example: Client requesting server to calculate factorial

// Client code (appears to call a local function)
let result = calculateFactorial(5);
console.log("Factorial of 5 is:", result);
// Server code (actual implementation)
function calculateFactorial(n) {
  if (n === 0) return 1;
  return n * calculateFactorial(n - 1);
}

4 Server stub receives message: Server stub unpacks (unmarshals) the parameters.
5 Server procedure execution: Server executes the actual procedure with the received parameters.
6 Server stub marshals result: Server stub packages the result into a response message.
7 Response sent back to client: RPC runtime sends the response back to the client.
8 Client stub receives result: Client stub unpacks the result and returns it to the client application.
9 Client continues execution: Client application receives the result and continues as if from a local call.

Key RPC Concepts

Marshaling/Serialization: The process of converting data structures or object state into a format that can be transmitted over a network.

Stubs: Proxies that make the remote call appear local. The client stub represents the server procedure locally, and the server stub receives the request and calls the actual server procedure.

IDL (Interface Definition Language): A language used to define the interfaces between clients and servers, enabling them to communicate with each other.

Network Transparency: The key goal of RPC is to make remote calls appear as local calls, hiding the complexity of network communication from the programmer.
